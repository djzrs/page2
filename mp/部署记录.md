# MediaPipe Web Samples 部署记录

## 这是什么

把 Google 官方示例仓库 [google-ai-edge/mediapipe-samples-web](https://github.com/google-ai-edge/mediapipe-samples-web)
在本地构建成纯静态站点，部署到本仓库的 `mp/` 子文件夹下，通过本账号的自定义域名 GitHub Pages 访问。

原仓库在线演示（大陆访问不畅）：https://google-ai-edge.github.io/mediapipe-samples-web/

本站访问地址：`https://pages.maikemaker.eu.org/mp/`

## 访问地址

- 入口：`https://pages.maikemaker.eu.org/mp/`
- 与本仓库已有的 `webai/`（TensorFlow.js coco-ssd 演示）互不干扰，根目录欢迎页保持原样。

## 做了什么

1. **拉取源码**：直连 GitHub 的 git 端口不通，改用 `https://gh-proxy.com/` 加速镜像克隆源码。
2. **安装依赖**：`pnpm install`，主要依赖是 `@mediapipe/tasks-vision / -audio / -text / -retrieval / -decision`。
3. **设置子路径**：原仓库 Vite 默认 `base = '/mediapipe-samples-web/'`（对应它自己的 GitHub Pages）。
   本站部署在自定义域名的 `/mp/` 子路径下，所以构建时改成 `base = '/mp/'`，否则 JS/CSS/WASM 会 404。
   构建命令：`pnpm exec vite build --base=/mp/`
4. **WASM 处理**：构建前的 `copy-wasm.js` 会把各任务的 `.wasm` 运行时从 node_modules 拷进 `public/wasm/`，
   一起打进产物，推理完全在浏览器本地跑，不需要服务器。
5. **部署**：产物（约 204 MB / 91 个文件）放入本 `mp/` 文件夹提交推送，GitHub Pages 自动发布。

## 目录结构

- `index.html` — 站点入口
- `assets/` — 构建出的 JS / CSS（含每个任务对应的 Web Worker）
- `wasm/` — MediaPipe 各任务运行时（vision / audio / text / retrieval / decision）
- `images/`、`*.png / *.jpg` — 示例用的图片素材

## 模型文件说明

站点本身不含模型权重。各任务的模型（`.task` / `.tflite` 等）在运行时按需从
Google 的 CDN（storage.googleapis.com 等）在线加载。经测试这些模型源在大陆可正常访问，
所以未把模型下载到仓库内。如以后模型源不可达，可将模型下载放进 `mp/` 下并把代码里的地址改为相对路径。

## 包含的示例任务（21 个）

- 视觉：图像分类、目标检测、人脸检测、人脸关键点、手势识别、手部关键点、姿态关键点、
  全身关键点、图像分割、交互式分割、图像嵌入
- 音频：音频分类、音频转写
- 文本：文本分类、文本嵌入、语言检测、语义检索、通用嵌入、文本转语音
- 决策：Decision Maker（规则 / JSON / 文本 / 视觉）
- 趣味：姿态控制 Chrome 小恐龙游戏（dino-game）

## 如何更新

以后想更新到新版本，重复以下步骤：

```bash
# 1. 拉最新源码
git clone https://gh-proxy.com/https://github.com/google-ai-edge/mediapipe-samples-web.git
cd mediapipe-samples-web
pnpm install
# 2. 以 /mp/ 为 base 构建
pnpm exec vite build --base=/mp/
# 3. 用 dist 内容覆盖本仓库的 mp/ 文件夹，提交推送即可
```

## 备注

- WASM 运行时体积较大（每个任务有 internal / module_internal 两份），是产物接近 200 MB 的主因。
- GitHub 单文件上限 100 MB，当前最大单文件约 25 MB，未超限。
- 部署时间为 2026-11-16。
